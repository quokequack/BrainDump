# **1\. Requisitos por tela do protótipo**

## **1.1 Tela inicial / Dashboard \- Em andamento**

A tela inicial deve funcionar como ponto de partida do aluno. Ela deve mostrar um resumo da participação acadêmica e permitir acesso rápido às ações principais.

**Funcionalidades:**

* Visualizar o total de pontos acumulados.  
* Visualizar a posição no ranking da turma.  
* Acompanhar o progresso pessoal.  
* Acessar rapidamente presença, ranking, atividades e histórico.  
* Ver próximas aulas ou presenças disponíveis.  
* Ver atividades complementares sugeridas.  
* Ver conquistas recentes.  
* Consultar o status de sincronização com o SIGAA.

**A tela deve conter:**

* Saudação ao aluno.  
* Total de pontos.  
* Posição no ranking da turma.  
* Progresso pessoal.  
* Próxima aula ou presença disponível.  
* Atividades complementares sugeridas.  
* Conquistas recentes.  
* Atalhos para ranking, presença, atividades e histórico.  
* Status de sincronização com o SIGAA.  
* Aviso de dados acadêmicos atualizados.

**Critérios atendidos:**

* Usabilidade: acesso rápido às tarefas principais.  
* Nielsen: visibilidade do status e reconhecimento em vez de memorização.  
* WCAG: textos claros, contraste e hierarquia visual.  
* Norman: signifiers, feedback e modelo conceitual.

\[Descrever a composição da tela inicial.\]

## **1.11 Tela de integração com o SIGAA**

A tela de integração com o SIGAA deve permitir que o aluno conecte sua conta acadêmica ao Knowly para sincronizar informações oficiais do sistema da universidade.

**Funcionalidades:**

* Conectar conta acadêmica ao SIGAA.  
* Sincronizar dados acadêmicos.  
* Atualizar dados manualmente.  
* Ver status da conexão.  
* Ver data e hora da última sincronização.  
* Desconectar conta do SIGAA.  
* Consultar quais dados podem ser sincronizados.  
* Receber mensagens de erro ou sucesso da conexão.

**A tela deve conter:**

* Explicação simples sobre a integração.  
* Botão “Conectar ao SIGAA”.  
* Status da conexão.  
* Data e hora da última sincronização.  
* Lista de dados que podem ser sincronizados.  
* Opção para atualizar dados manualmente.  
* Opção para desconectar a conta.  
* Aviso de privacidade sobre o uso dos dados acadêmicos.  
* Mensagem de erro caso a conexão falhe.  
* Mensagem de sucesso caso a conexão seja realizada.

**Dados que poderiam ser sincronizados:**

* Nome do aluno.  
* Curso.  
* Turma.  
* Período.  
* Disciplinas matriculadas.  
* Horários de aula.  
* Registros de presença.

# **2\. Requisitos por tela do protótipo \- Docente** 

## **2.1 Painel do docente**

A tela inicial do docente deve funcionar como ponto de partida do professor. Ela deve reunir, em um só lugar, a situação das turmas e os alertas automáticos, substituindo o acompanhamento manual feito em planilhas.

**Funcionalidades:**

* Visualizar um resumo semanal de cada turma.  
* Receber alertas automáticos de risco de evasão.  
* Visualizar a quantidade de alunos que precisam de atenção.  
* Acompanhar a queda de engajamento das turmas.  
* Acessar rapidamente a lista de alunos em risco.  
* Acessar as turmas em que leciona.  
* Consultar dados de presença e notas sincronizados com o SIGAA.

**A tela deve conter:**

* Saudação ao docente.  
* Lista das turmas em que leciona.  
* Resumo semanal de cada turma (presença, entregas e engajamento).  
* Quantidade de alunos em risco por turma.  
* Feed de alertas automáticos recentes.  
* Destaque para os alunos que precisam de atenção imediata.  
* Atalho para a lista de alunos em risco.  
* Status de sincronização com o SIGAA.

**Critérios atendidos:**

* Usabilidade: visão rápida da situação das turmas, sem trabalho manual.  
* Nielsen: visibilidade do status e reconhecimento em vez de memorização.  
* WCAG: textos claros, contraste adequado e indicadores que não dependem só de cor.  
* Norman: feedback, signifiers e modelo conceitual.

**Como o app resolve isso:**

Espaço para preencher:  
\[Descrever como o painel reúne o resumo das turmas e os alertas.\]
